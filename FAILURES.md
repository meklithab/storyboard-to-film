# Failures and workarounds

| Problem | What happened | What was tried / fixed |
|---|---|---|
| New storyboard saved as `new_storyboard.py` | JSON content in a `.py` file, so no stage could read it | Copied it verbatim to `storyboard.json`, fixed one stale motion line (shot 04 mentioned a bus that is not in its image), removed the duplicate file |
| Old single-voice pipeline | `durations.json` was a flat `shot_id → seconds` map and every shot had one WAV; the new story has two speakers | Introduced per-role WAVs, a nested durations entry with `total`, a shared clip/pad helper, and updated narration, subtitles, radio cut, shots and assembly together |
| Proverb speaker could be a typo | Would only surface as a missing file at assembly | `validate.py` now checks the speaker exists in `voices` and `characters`; verified with a deliberate bad value |
| Runtime could drift outside the brief | A short or long plan would waste generations | Validation now checks 60–90 s including the end card; verified with a 7-shot probe (59 s → error) |
| `ffmpeg` not on this shell's `PATH` | Assembly and radio cut could not be executed here | Scripts fail with a clear message; the code path is documented and `tests/test_timeline.py` verifies the timing offline. Use a machine with FFmpeg installed for the export |
| `google.genai` missing from the system Python | TTS could not be imported in the bare shell | Use the project virtual environment (`pip install -r requirements.txt`); `narration.py` imports the SDK lazily so validation/tests still run without it |
| No `outputs/music/chosen.wav` yet | Assembly would have no score | `music.py` checks for it and assembly degrades to a warning + music-less mix instead of failing; candidates come from the ACE-Step notebook |
| No Wan 2.2 clips yet | GPU queue is the binding constraint | `shots.py` falls back to an FFmpeg slow pan/zoom from each keyframe; dropping a `<id>_wan.mp4` into `outputs/shots/` automatically overrides it |
| TTS voice availability is provider-dependent | A configured voice name (`Puck`, `Sulafat`) may be rejected | Retry once, then fall back through `Kore`, `Puck`, `Sulafat`; every failed attempt is logged and the used voice is written to `voices_used.json` |
| Audience said the grandmother did not look Ethiopian / Habesha | The approved v1 sheet came from a generic "elderly grandmother" prompt, so the character did not match the audience's frame of reference | Rewrote the character description and reference prompt with explicit Habesha features, added `make refresh_reference`, and rebuilt all reference sheets, keyframes and shot clips from the new approval |
| `gemini_text` smoke test returned 503 UNAVAILABLE | High demand on `gemini-3.8-flash`; the call failed after ~100 s of retries | `smoketest.py` now tries `gemini-3.8-flash`, then Flash-Lite, then `gemini-2.5-flash`, logging each attempt; a single busy model no longer fails the smoke test |
| Gemini TTS hit `429 RESOURCE_EXHAUSTED` at shot 04/grandmother | Free tier allows only **3 `generate_content` requests/minute** for `gemini-3.8-flash-tts`; the API asked to retry in ~42 s | `narration.py` now paces calls (default 21 s apart, override with `GEMINI_TTS_MIN_INTERVAL_SECONDS`), parses the API's `retryDelay` and waits, does not waste quota trying other voices on a quota error, and resumes from cached lines on the next `make narration` |
| Gemini TTS hit the **10 calls/day** project quota with `retryDelay: 48565s` (~13.5 h) | The first 12 of 20 lines were generated; the API asked to wait over 13 hours | The run was stopped instead of sleeping; cached lines are safe. `make narration` resumes after the reset (or with a different Google project key). Remaining work continued with the approved reference and procedural score while waiting. |
| ACE-Step score could not be generated here | No Kaggle GPU run was available for `notebooks/acestep_music.ipynb` | `pipeline/music.py` now synthesises a seeded 83 s krar-like instrumental from the storyboard's own `music` block using stdlib `wave`, logged as `procedural-krar-fallback` |
| Measured film was 98.8 s, over the 60–90 s limit | Real Amharic TTS lines averaged ~9.6 s each, far longer than the 8 s plan; TTS quota was exhausted so re-recording was impossible | Added `pipeline/retime.py`: trims 0.1–0.9 s of dead air per clip, rewrites `durations.json`, keeps raw takes in `outputs/narration/raw/`. With the 4 s intro added, the derived speed-up is 1.068x and both exports measure **89.0 s** |
| `ffmpeg` was installed by winget but not on the shell `PATH` | `make shots` / `make assemble` reported "ffmpeg not found on PATH" | `common.ffmpeg_bin()` resolves the winget shim and common install folders; `shots.py`, `assemble.py` and `radio_cut.py` all use it |
| Final assembly crashed with exit code 0xC0000005 at the end-card step | `drawtext` had no font (fontconfig error) and the unescaped Windows drive colon broke the filtergraph | `find_font()` picks `arial.ttf`/`segoeui.ttf`/DejaVu and the path is quoted with the colon escaped (`'C\\:/Windows/Fonts/arial.ttf'`); assembly then exported both finals |
| Audience feedback: the grandmother did not read as Habesha | The same character-identity issue surfaced in the near-final visual session, after the first reference approval | Rewrote `characters[*].description` and `reference_prompt` with deep warm-brown skin, high cheekbones, braided hair in a white netela, gold hoop earrings and a white kemis with gold/red tibb; regenerated v1–v4, hashed references into the keyframe cache, and rebuilt all dependent shots |
| Audience feedback: shots were not descriptive enough and there was no setup | Image prompts listed subjects but lacked story context, setting, costume and lighting detail; the film opened mid-action | Every `image_prompt` now names the location, action, background, light and visible faces, and includes `reason` + `shot_size` in the generation prompt. Added a 4 s `intro` block with title and logline, rendered by `assemble.py`, with its duration subtracted in `retime.py` and added to subtitle timestamps |
| Audience feedback: the horizontal export was not really horizontal | `assemble.py` blurred and pillarboxed the 720×1280 master into 1280×720, so the wide file was still a vertical composition | Added `format.horizontal_prompt_suffix`; `keyframes.py` now generates 1024×576 wide compositions from the same reference, `shots.py` renders 1280×720 clips, and `assemble.py` builds a separate horizontal timeline with wide intro/end cards and its own subtitle styling. Verified both finals are 1280×720 and 720×1280 at 89.0 s |

Earlier logged model failures and latencies remain in `runs.jsonl`; unsuccessful
calls are kept as `success: false` lines rather than deleted.
